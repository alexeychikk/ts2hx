# 0005 — How TypeScript maps to Haxe (definition of "complete")

Status: accepted (2026-11-14)

The new engine is complete when every **Supported** row below has passing
conformance cases on JS, C# and C++. **Degraded** constructs compile and run
but differ in documented edge cases, and print a `TODO(ts2hx)` comment.
**Out of scope** constructs become an `Unsupported` placeholder (a TODO
comment plus `Ts2hx.unsupported("…")`, which throws at run time). They never
produce broken Haxe: the conformance case `unsupported/compiles` feeds them
all and must build on every target. "Runtime" means the `ts2hx` package
([0002](0002-targets-and-runtime.md)).

## Modules and names

| TS | Haxe | Notes |
| --- | --- | --- |
| file `a/b/my-file.ts` | module `<rootPackage>.a.b.My_file` | Packages are lower-cased and module names capitalised; module names that collide (case-insensitively) get `_2`, `_3`, …, and Haxe std type names (`Math`, `String`, …) get `_`. Module-level values are named by the ProjectModel's per-module table (`ModuleInfo.fields`): Haxe keywords (`cast`, `dynamic`, `untyped`, `inline`, `macro`, `operator`, `overload`, …) get `_`, and a name colliding with another value, the module, a typedef of the module, `__init` or a root package gets `_2`, … Values keep their case (`MAX`, `Square`). Type names (classes, typedefs, enums, namespaces, hoisted classes; `ModuleInfo.types`) are unique per Haxe package across modules, case-insensitively and against the package's module names and `Main`, because Haxe forbids two types of one package with the same name: modules keep their types in file name order, and a later colliding type is renamed `Name_2`, …, avoiding its module's other names. A local named like a root package the output references (`haxe`, `ts2hx`, the project's top package) gets `_`. |
| top-level function / const / let | module-level `function` / `static var` (Haxe 4.2 module fields) | Non-constant initialisers move into a generated `__init()`. |
| top-level statements and side effects | generated `__init()` per module | `Main` calls every module's `__init()` once, in Node's ESM evaluation order (post-order DFS over imports from the entry). That keeps cycles and side-effect order. Imports TS elides are not followed, as in tsc's output: an import none of whose bindings is read as a value (only types, only `typeof`), `export type`, and `export *` of a module without values. Under `verbatimModuleSyntax` only `import type` and `export type … from` are dropped. |
| `import {a as b}`, default, `import * as ns`, re-exports, `export default <expr>` | references resolved through the alias chain to the declaring module: `pack.Module.field` | Re-export-only files emit nothing. `ns.x` becomes a direct reference; a namespace object used as a value is `Unsupported`. `export default <expr>` is a `default_` module var assigned in `__init()`, as is `export default x` of a `let`/`var` (ESM snapshots it); a function or `const` is aliased. Fields and locals never take the name of a module of the empty package, which references would otherwise resolve to. `export =` is out of scope (TS rejects it in ESM). |
| import cycles | supported | Haxe resolves type cycles. Init order is explicit (above). |
| dynamic `import()` | Out of scope | |
| `namespace N {}`, `namespace A.B {}` | class `N` with `public static` members, nested namespaces and enums as `N_M` | Statements run in the module's `__init()`. Namespace blocks with the same name merge into one class; merging with a top-level class adds statics to that class. Merges with a function, an enum or a type are `Unsupported`; ambient namespaces emit nothing. Type names (interfaces, aliases, enums, namespaces) get `_` when they would shadow a module of the empty package or the generated `Main`. |
| `declare global`, ambient declarations in the project | JS: externs. C#/C++: `#error` | |
| npm packages | JS: externs generated from `.d.ts` (`@:jsRequire`). C#/C++: `#error` naming the package | One extern class per package, `<rootPackage>.externs.<Package>`, with the members the project reads: a function with one signature is typed (primitives; everything else `Dynamic`), anything else is a `static var` of type `Dynamic`. Types a package declares map to `Dynamic` (or a `Dict`). A package is a module resolved to a `.d.ts` under `node_modules` other than `@types/node`; a default import is used as the namespace (`pkg.member`), so calling it or reading a namespace as a value is `Unsupported`. The legacy shims are ported to `ts2hx.npm.*` and work on all targets (degraded): lodash (the common array/object/function helpers, without `debounce`/`transform`; an unported member is `Unsupported`), joi (`object`/`string`/`number`/`boolean`/`array`/`any` with `required`/`min`/`max`/`integer`/`valid`/`items`, joi's messages; object keys are checked in `Reflect.fields` order, alphabetical on C#/C++), nanoid (ids from `Math.random`), seedrandom (exact ARC4 sequence; only the call form, no `int32`/`quick`/`state`). |
| Node built-ins | `process.argv`, `process.exit` and `process.stdout`/`stderr.write` through `ts2hx.Process` | Native targets build `argv` as `[program, program, ...Sys.args()]`. Everything else (fs, path, …) is out of scope. |

## Types

| TS | Haxe | Notes |
| --- | --- | --- |
| `number` / `string` / `boolean` | `Float` / `String` / `Bool` | `Int` only at index sites (0002). |
| `any` / `unknown` / `object` / `never` | `Dynamic` / `Any` / `Dynamic` / `Dynamic` (`Void` as a return type) | |
| `T \| null \| undefined`, optional `?` | `Null<T>`, `@:optional var` | null and undefined are merged (0002). |
| interface / object type alias | `typedef` anonymous structure | Methods become `function f():R;` and readonly fields `final`. When a class is used as a structure that has optional members it lacks (through `implements` or any assignment the ProjectModel finds), those members are added to the class as `Null<T> = null` fields. That is required on C# (0002), so it is never done with a bare `cast`. A member is added to the topmost class that lacks it, not repeated in subclasses. A member a subclass declares as a method or accessor is not added, because Haxe forbids that next to an inherited var: it is reported `Unsupported`, and reading it on the base class fails on C#. A structure member that some class used as that structure implements with an accessor is read through `Reflect.getProperty`, since Haxe only runs a getter on a statically known class. Writing such a member is `Unsupported`. |
| index signature, `Record<string,V>` | `ts2hx.Dict<V>` | Insertion-ordered. `Record<'a'\|'b', V>` becomes a structure. |
| union of literals of one primitive | that primitive (`String`/`Float`) | String-literal unions used as discriminants keep `==` comparisons. |
| other unions | `Dynamic` | **Flow narrowing is reconstructed**: wherever the checker's narrowed type maps to a different Haxe type, the frontend emits `cast`. That covers discriminated unions, `typeof`/`instanceof`/`in` guards and user type guards. |
| intersection of object types | merged anonymous structure | Intersections involving a class or primitive become `Dynamic` (degraded). |
| generics, constraints, defaults | type parameters, `T:Constraint` | Classes, function declarations and class methods keep their type parameters. A type parameter is erased to `Dynamic` (degraded) when its constraint is not a project class or typedef (`{ length: number }`, `number`, `keyof T`, `object`), or when Haxe cannot declare it: arrows, function expressions, generic signatures of function values, and methods of interfaces and aliases. An erased class parameter is dropped from the class's type arguments. Default type args are filled from checker instantiations. Operators on a type parameter follow its primitive constraint (`N extends number` compares as a number). Generic interfaces and aliases are inlined as structures of their instantiation. A callback passed to a project function with fewer parameters than the expected function type is padded. A method declared to return `this` returns its class, and a call to it is cast to the receiver's class. |
| conditional, mapped, `keyof`, indexed access, `typeof`, template-literal types, utility types | resolved by the checker at each use site and mapped from the result | Declarations that stay generic over such types fall back to `Dynamic`. Degraded, but valid. `o[k]` with a computed string key on an object that is not an array, string, dictionary or enum (e.g. `K extends keyof T`) is `Reflect.getProperty` cast to the checker type, and an assignment to it is `Ts2hx.setProperty`, which evaluates to the value. |
| tuples | `Array<Dynamic>` with casts at element reads | Degraded typing. Runtime behaviour is exact. |
| function types, overloads | Haxe function types. The implementation signature is emitted, for functions, constructors, methods and statics alike | Callbacks with fewer parameters than the expected function type are padded or wrapped by the frontend. |
| `as`, `satisfies`, `!` | `cast` / dropped / dropped | |
| enums (numeric, string, const) | `enum abstract E(Float) from Float to Float` / `(String)` | Member reads are casts to the value type, so arithmetic and string operations work as in JS. Reverse mapping `E[v]` goes through a generated static `name()` (`name_2` if a member is called `name`); the last duplicate value wins, as in JS. `Object.keys/values/entries(E)` are computed at compile time in JS order. Heterogeneous enums are `Dynamic`-backed (degraded). Computed members and an enum object used as a value are `Unsupported`. |
| `symbol`, `unique symbol` | `ts2hx.Symbol` (identity object) | Only well-known `Symbol.iterator` and `Symbol.asyncIterator` have protocol meaning. |
| `bigint` | Out of scope | |
| `.d.ts` in the project | types used, no output | |

## Classes and functions

| TS | Haxe | Notes |
| --- | --- | --- |
| class, `extends`, `super(...)`, override | class | **Field initialisers move into the constructor after `super()`**, which is TS order: parameter properties first, then initialisers. A constructor whose `super()` is not a top-level statement while it has initialisers is `Unsupported`. A missing constructor is generated with forwarding when the class has a base and initialisers; otherwise Haxe inherits the parent's. `override` is emitted only over an implemented ancestor method, because Haxe rejects it over an `abstract` one. A field redeclared in a subclass is declared once, on the topmost class. Fields of a class whose ancestor's constructor or initialisers call a method on `this` (or let `this` escape) are `Null<T>`, so they read as `undefined` before initialisation, like JS. `extends` of non-project classes is `Unsupported`. |
| parameter properties, `readonly` | fields assigned in the constructor, `final` | A base `readonly` becomes `var` when a subclass redeclaration writes it: as mutable, with an initialiser, as a parameter property, or by assigning it in its constructor. |
| static members, static blocks | statics. Static blocks join the module `__init()` | Statics inherited through a subclass are rewritten to the declaring class. In JS a write through the subclass creates a separate static of the subclass, and `this` in an inherited static method is the subclass; neither is emulated. So a write to an inherited static through a subclass (`Sub.n = 1`, `this.n++` in a static of `Sub`) is `Unsupported`, and so is a call `Sub.m()` of an inherited static method that writes a static through `this`, reads through `this` a static `Sub` redeclares, or uses `this` as a value (`new this()`), following `this.f()` calls. Calls through a class value (`const K = Sub; K.m()`) and `super.m()` in statics are not detected and use the declaring class. A constant initialiser stays on the field. Others are assigned in the module `__init()` in source order, together with the static blocks. A hoisted class (see class expressions) runs them where its declaration was. `this` in a static method or block refers to the class. |
| `private`, `protected`, `#private` | `private` (Haxe private behaves like protected). `#x` is renamed `__x` | `#x` gets the suffix `_<n>` (`__x_2`) when an ancestor also declares `#x`, because Haxe forbids redeclaring a field. `#x in o` is `Unsupported`. |
| abstract classes and members | `abstract class` (Haxe 4.2+) | |
| accessors `get`/`set` | properties `(get, set)` / `(get, never)` / `(never, set)`, with public `get_x`/`set_x` | The property is declared once, on the topmost class with the accessor. Subclasses override only the methods. A setter returns the assigned value, so `(o.x = v)` is `v` even after an early `return;`. `override` follows the method rule above. `private` and `protected` accessors give a private property. An accessor that overrides a field, adds a kind its base lacks, or is `#private` is `Unsupported`. |
| object-literal accessors | Degraded: lowered to an anonymous class instance | |
| class expressions, local classes | hoisted to module-level classes named after the class or its `const` binding (`Class_` otherwise), renamed `_2`… on collision; like every class and typedef name, a Haxe std type name (`Date`, `Map`, …) gets `_` | Captured locals (and local functions) are passed as leading constructor parameters and stored in private fields `__<Class>_<local>`. The constructor reads them from those parameters, so they are available before and inside `super(...)`. A hoisted subclass of a hoisted class also takes its base's captures and passes them first to `super`, through a generated constructor when it has none. Statics are shared by all evaluations of the expression. A capture that is reassigned, read in a static member, or a `new` outside the captured locals' scope is `Unsupported`. |
| class values: `typeof C`, `new` on a value | the Haxe `Class`; `new (class {…})()` is a direct `new` of the hoisted class; `new K()` on any other value whose instance type is a project class is `(cast Type.createInstance(K, [args]) : C)`, with omitted optional arguments passed as `null` | `new` on a class value whose class captures locals (a class returned from a function that closes over its parameters) or has a rest parameter is `Unsupported`, as is `new` on a value whose instance type is not a project class. |
| mixins, `Object.setPrototypeOf`, prototype mutation | Out of scope | |
| `instanceof` | `Std.isOfType` | Primitives are handled by the runtime. `Array` and project classes are mapped so far. |
| functions, arrows, closures | local functions and arrows | Haxe closures capture by reference and `this` lexically, which matches arrows. Function declarations stay in source order, because Haxe types a local function where it is declared. A function that is used before its declaration, called by such a function, or captures a `let`/`const` declared after it becomes a `var f:FnType = null` at the top of its block. It is assigned right after the last `let`/`const` it captures. If an earlier statement may reach it (directly or through another function of the block), it is assigned at the top instead, and the `let`/`const`s it captures are hoisted like `var`s (`Null<T>`, assigned at their declaration). A generic one is `Unsupported`. A `let`/`const` read by any closure (arrow, function expression, nested function) that appears before its declaration is hoisted the same way. A value-returning function whose end is reachable (the binder's `HasImplicitReturn`) ends with `return null`, and a bare `return;` in it returns `null`. When its Haxe return type is not nullable, TS guarantees the end is unreachable (e.g. after a `never` call), so it ends with `throw "unreachable"`. |
| `this` in object-literal methods | a self local: `{ var self = null; self = {…}; self; }` | Arrows inside the methods see the same `this`. |
| `function` expressions using a dynamic `this`, `call`/`apply`/`bind` with a foreign `this`, `arguments` | Degraded (`bind` keeps the receiver) / out of scope | |
| default parameters | Haxe constant defaults, otherwise `if (p == null) p = …` | Explicit `null` triggers the default (degraded, see 0002). |
| rest parameters, spread arguments | `...rest:T` (`haxe.Rest`). The arguments that reach a rest parameter become one spread array (`f(a, ...[b].concat(xs))`), copied element by element when the element types differ, since Haxe spreads only a lone array into a rest. Spread into a fixed-arity call goes through `Reflect.callMethod` or an inlined unpack | A spread into a parameter before the rest is unsupported. |
| decorators (legacy and TC39) | Out of scope: a TODO plus `@:ts.decorator("…")` metadata on the class or member. The decorator call is not executed | A warning per decorator. |

## Statements and expressions

| TS | Haxe | Notes |
| --- | --- | --- |
| `var`/`let`/`const`, TDZ | `var`/`final`. The frontend hoists `var` to its function as `Null<T>`; C-style `for` is lowered by the `lowerCFor` pass | Per-iteration `let` bindings captured by closures in loops get a fresh copy. |
| `if`/`while`/`do`/`for`/`for…of`/`for…in` | lowered by a pass: C-style `for` becomes `while` with correct `continue`. `for…of` over arrays, strings, collections and `matchAll` iterates an array with Haxe `for`. Over generators, iterators and classes with `[Symbol.iterator]()`, it runs `Iter.iterator`/`Iter.step` and calls `Iter.close` (the iterator's `return`) when the body leaves early | |
| `switch` with fall-through, `break` inside a switch inside a loop, non-constant cases | the `lowerControlFlow` pass: the subject is read once into a `final`, each case is an `===` test. Without fall-through, an if-chain in clause order with `default` as the final `else`; with fall-through, a clause index (`c0 ? 0 : c1 ? 1 : default`) and `if (index <= i)` per body. A `break` left inside a body exits a `do {} while (false)` wrapper | No Haxe `switch` is emitted (its `break` would break the loop). A `default` sharing a body with a case whose test has side effects takes the clause-index form so tests run in JS order. A `let`/`const` used across clauses is `Unsupported`. A value function whose lowered body Haxe sees falling off its end gets `throw "unreachable"`. |
| labels, labelled `break`/`continue` | `lowerControlFlow`: a label on a loop or `switch` names it; a labelled block that is broken becomes `do {} while (false)`. A jump to the innermost Haxe loop stays a `break`/`continue`; one that crosses loops sets a `Bool` flag declared before its target and breaks, and each crossed loop is followed by `if (flag) break;`, or at the target by the jump itself | Runs before `lowerCFor`, so a flagged `continue` of a C-style `for` still runs its update. |
| `try`/`catch`/`finally` | the `lowerFinally` pass, run before `lowerControlFlow`. It uses ECMA-262 completion records: a jump out of `try` or `catch` stores a code (and the returned value), then breaks out of a labelled block. A throw is caught and stored the same way, and the `catch` body runs under its own `try`. `finally` runs next, then an if-chain resumes the stored completion. A jump inside `finally` stays as written, so it overrides the completion as in JS | `catch` without a binding is supported. The caught value goes through `ts2hx.Error.caught` (ADR 0002) |
| destructuring (declaration, parameter, assignment, `for…of`, `catch`), defaults, rest | the source is stored in a temporary, then each name is bound from a field or index read. Defaults apply when the read is `null` | `catch` patterns bind from a temporary holding the caught value |
| spread in arrays and objects | `concat` for arrays. Any iterable spreads through `toArray()` / `Iter.toArray`. An object spread is an object literal that copies the data properties of the source's static type (no class methods or accessors) in JS key order, and a later key replaces an earlier one in place. A spread into a `Record` fills a new `Dict` | A spread source whose type includes `null`/`undefined` is unsupported, unless a source's keys are unknown statically (a type parameter or `any`): then the whole literal is filled by reflection (`Ts2hx.assign`) in source order, with the target's `Reflect.fields` key order (degraded) |
| `?.`, `??`, `??=`, `\|\|=`, `&&=` | `??` is Haxe 4.3 `??`. A `?.` chain stores the guarded value in a temporary and evaluates to `c == null ? null : rest-of-chain`. Logical assignments read the target once (its object and index stored) and write only when the operator says so | `a?.[i]` and `a?.()` are lowered the same way. |
| truthiness, `!`, `\|\|`, `&&` | type-directed (0002) | A value whose type is only `null`/`undefined` (e.g. narrowed by assignment) is `false` only when it is a literal; any other expression goes through `Ts2hx.truthy`, because TS keeps that narrowing across closure calls that reassign the variable. `String`/template of such a value is `x == null ? "undefined" : Ts2hx.string(x)` for the same reason. |
| `==`/`!=` (loose) | `==` when both sides have the same primitive or class type, otherwise `Ts2hx.looseEq` | `===` becomes Haxe `==`. |
| arithmetic, `%`, `**`, bitwise, `++` on fields and indexes | Float arithmetic, `Num.pow` (JS `NaN`/`±1 ** ±Infinity` results), `Num.toInt32`, `Num.shl`/`shr`/`ushr` | `+` with a string operand converts the other side with `Num.toString` or `Ts2hx.string`. A `String`-typed operand of `+`, `+=` or a template that is a variable, field, element, cast or project call goes through `Ts2hx.stringOperand`, because TS lets `undefined` reach a `string` (a field read before init passed on, an out-of-range element): on C#/C++ it prints `undefined` instead of `null`, on JS it inlines to the value. Its cost is one inlined null check per operand: on 5M concatenations `"[" + s + "]"`, within noise on C# and 3–6% on C++. Other operations on such a value (`String(s)`, methods, `.length`, a property key) follow Haxe `null` (degraded). |
| `typeof x` | static constant when the type is known, otherwise `Ts2hx.typeOf` | A class value (anything with call or construct signatures) is `"function"`, and so is a `Class` at run time. |
| `in`, `delete` | `Dict` `exists`/`remove`, otherwise `ts2hx.Obj.has`/`Obj.delete` | `in` on an array or a string is `Unsupported`. |
| comma, `void`, assignment as an expression | block expressions; Haxe assignments are expressions | A `void` call used as a value becomes `{ f(); null; }`; `return f();` in a `void` function becomes `f(); return;`. `void x` is `null`, or `{ x; null; }` when `x` has effects. A compound assignment to a module var whose value is used is spelled `m = m * v`: Haxe 4.3.7's JS generator references an elided `_Fields_` class for `m *= v` as a value. |
| template literals, tagged templates | `+` chains through `Num.toString` or `Ts2hx.string` (`null`/`undefined` literals print as constants) / a call with a strings array and the values | |
| regex literals and methods | `ts2hx.RegExp` | `exec`/`test`/`lastIndex`/flags, and `String` `match`/`matchAll`/`replace`/`replaceAll` (string or function replacer)/`split`/`search`. Match arrays are `Array<String>` with `index`/`input`/`groups` read through `RegExp` statics. `matchAll` gives a `RegExpStringIterator` that for-of, spread and `Array.from` consume. A function replacer is wrapped into an argument-array callback. 0002. |
| generators, iterators, `yield*` | The frontend wraps a generator body as `return new ts2hx.Generator<T>(function(ctx) …)`. The last pass, `lowerGenerators`, turns that step function into a `switch` on `ctx.state`: each `yield` returns through `ctx.yieldTo` (or `ctx.delegateTo` for `yield*`), and `return` goes through `ctx.finish`. Locals are hoisted into the enclosing function. `next`/`return`/`throw` map to `next`/`doReturn`/`doThrow`. `Generator<T>` is `ts2hx.Generator<T>`, and `Iterator`/`Iterable`/`IterableIterator<T>` are `ts2hx.JsIterable<T>`. A `[Symbol.iterator]()` member is named `__ts2hx_iterator`, and `x[Symbol.iterator]()` becomes `Iter.iterator(x)`. | A `try` around a `yield` is routed by a `catch` around the dispatch loop. `return()` reaches `finally` blocks but not `catch` clauses. A `yield` nested in an expression runs first, and what JS evaluates before it is kept in temps. A `yield` in a branch that may not run (`&&`, `\|\|`, `??`, `?:` arms, `??=`) is `Unsupported`, as is a `yield` in a `try` with several catches. Loop closures inside a generator share the hoisted binding instead of getting a fresh per-iteration copy. |
| `async`/`await`, `for await`, async generators | the same state machine driven by `ts2hx.Promise` | Microtask ordering matches Node (0002). |
| `eval`, `with`, `new Function`, `Proxy`, `Reflect.*` (ES), `WeakRef`, `FinalizationRegistry` | Out of scope (`WeakMap`/`WeakSet` are degraded to strong maps) | |

## Standard library (bound by checker symbol through `stdlib/bindings`)

| Area | Runtime | Notes |
| --- | --- | --- |
| `console` | `ts2hx.Console` | `util.inspect` subset: nested objects and arrays, `Map`/`Set`, class names, Node's line breaking at 80 columns and depth 2. No `%` format strings and no function names. |
| `String.prototype.*`, `String.*` | `ts2hx.JsString` | All ES2022 methods with UTF-16 semantics; `RegExp` arguments are left to `RegExp`. Degraded off JS: `localeCompare` (case-insensitive, then code units, no options), `normalize` (Latin-1 letters with combining accents only), locale variants map to the plain ones. |
| `Number`, `parseInt`, `parseFloat`, `isNaN`, `toFixed`, `toString(radix)`, `toPrecision` | `ts2hx.Num` | Digits come from the exact decimal value of the double, as in V8; `toString(radix)` ports V8's algorithm. |
| `Math.*` | Haxe `Math` and `ts2hx.JsMath` | JS `Math.round` semantics, variadic `max`/`min`/`hypot`, `cbrt` from fdlibm (libm is not correctly rounded everywhere), constants inlined. |
| `Array.prototype.*`, `Array.from`/`of`/`isArray` | `ts2hx.JsArray` | Callbacks receive `(value, index, array)`. `sort` defaults to string comparison and is stable. `splice` supports insertion. `length` is writable. |
| `Map`, `Set`, `WeakMap`, `WeakSet` | `ts2hx.JsMap` / `ts2hx.JsSet` | Construction from an array, a `Map`/`Set` or their iterators. `for…of`, spread and `Array.from` over them and their `keys`/`values`/`entries`. Degraded: `WeakMap`/`WeakSet` hold their keys strongly. |
| `Object.keys`/`values`/`entries`/`assign`/`fromEntries`/`freeze` (no-op), `for…in` | `ts2hx.Obj` (a `Dict` enumerates itself) | JS key order on every target from the literal and class records (0002). `fromEntries` returns a `Dict`. |
| `JSON.parse`/`stringify` (indent, replacer array or function, reviver, `toJSON`) | `ts2hx.Json` | Key order from `Obj.keys` (0002). Degraded: a field holding `undefined` is printed as `null` (0002). |
| `Promise.*`, `setTimeout`/`setInterval`/`clearTimeout`/`clearInterval`/`queueMicrotask` | `ts2hx.Promise`, `ts2hx.EventLoop` | `then`/`catch`/`finally`, `resolve`/`reject`/`all`/`allSettled`/`race`/`any` (array arguments; other iterables are `Unsupported`), promise and thenable adoption, `AggregateError`. Callbacks are padded to the arity the runtime calls them with (0002). `setImmediate` and `process.nextTick` are not bound. |
| `Error` family, `Date` (UTC only), `Intl`, typed arrays | `ts2hx.Error` family / `ts2hx.JsDate` degraded (no local time zones) / out of scope / `Uint8Array` family degraded to `Array<Float>` | |
| any other lib member | `Unsupported` with the member name | One warning per run lists them, with the npm members no shim covers. |
